# Team Finder (TFUA)

Telegram-бот для пошуку тімейтів: гравці створюють анкети з іграми та рангами, шукають одне одного за фільтрами й обмінюються контактами після взаємної згоди.

## Можливості

- Анкета: ім'я, до 5 ігор з рангами, вік, стать, опис
- Пошук за іграми, діапазоном рангів, статтю та віком; без повторів уже переглянутих анкет
- Запрошення в гру → контакти відкриваються лише після прийняття
- Розділ «Мої тімейти» зі списком матчів
- Неповнолітні бачать і взаємодіють лише з неповнолітніми, дорослі — з дорослими
- Скарги та повідомлення про проблеми надходять у канал адміністратора
- Адмін-панель: `/admin`, `/ban <id>`, `/unban <id>`, розсилка
- Захист від спаму (ліміти дій), незавершені діалоги переживають перезапуск

## Технології

Node.js, TypeScript, [Telegraf](https://telegraf.js.org/), SQLite ([better-sqlite3](https://github.com/WiseLibs/better-sqlite3)).

## Запуск

Потрібні змінні оточення (локально — у файлі `.env`, на сервері — у налаштуваннях):

| Змінна | Опис |
|---|---|
| `BOT_TOKEN` | токен бота від @BotFather |
| `ADMIN_ID` | Telegram ID адміністратора |
| `CHANNEL_ID` | ID каналу для скарг (`-100...`) або `@username` |
| `DB_PATH` | шлях до файлу бази (необов'язково, за замовчуванням `database.db`) |

```bash
npm install
npm run dev      # розробка з автоперезапуском
npm test         # автотести
npm run build && npm start   # продакшн
```

> Не запускайте локально з тим самим токеном, що й на сервері — Telegram дозволяє лише один екземпляр бота. Для розробки створіть окремого тестового бота.

## Структура

```
src/
  index.ts          точка входу: запуск бота
  bot.ts            створення бота, middleware, порядок обробників
  config.ts         змінні оточення
  constants.ts      тексти кнопок, ліміти, ігри та ранги
  state.ts          стан діалогів і пошуку (зберігається в базі)
  domain/           чиста логіка: валідація, вік, ранги
  services/         пошук анкет, обмеження частоти дій
  ui/               клавіатури та форматування повідомлень
  handlers/         обробники: анкета, пошук, запити, скарги, адмінка
  database/         робота з SQLite, міграції схеми (db.ts)
tests/              автотести (node:test)
```

Зміни схеми бази додаються новою міграцією в кінець списку в `src/database/db.ts` — існуючі міграції не змінюються.
